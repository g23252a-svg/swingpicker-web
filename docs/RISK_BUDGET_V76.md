## 1. 켈리가 종목별 분율만 내고 합계를 보는 사람이 없었다

`kelly_calibrator.size_positions`는 행마다
`f = clip(f_raw × 0.5, 0, max_allocation=0.25)` 를 구해
`켈리_금액 = total_capital × f` 를 찍는다. 종목당 25% 상한은 있는데
**하루 합계 상한도, 보유 중인 이전 포지션과의 합산도 없다.**

배치 121일 실측 (계좌 1,000만원):

| | 값 |
|---|---|
| 하루 배분 합계 중위 | 14.5% |
| 하루 배분 합계 최대 | **183.8%** (2026-04-24, 28종목, 19,345,780원) |
| 합계 100% 초과일 | 19/121일 (16%) |
| **5일 중첩 노출** 중위 | **133.0%** |
| 5일 중첩 노출 최대 | **721.6%** |
| 중첩 300% 초과일 | 28/117일 |

보유기간이 5일이므로 t일 포지션은 t+4까지 살아 있다. 그런데 t+1, t+2…
배치는 이전 포지션을 모른 채 계좌 전액을 다시 배분한다.
화면의 `켈리_수량`은 **현금 계좌로 집행할 수 없는 숫자**였다.

MDD -173%는 **파산**이다. 계좌가 0을 지나 빚으로 간다.

### 왜 선착순이 아니라 날짜별 트랜치인가

총노출 상한만 두면 한 날이 계좌를 다 먹고 다음 나흘을 굶긴다.
실측에서 2026-08-25 배치 하나가 100%를 가져가 이후 4개 배치의 배분이 0이 됐다.
진입일 코호트마다 `BOOK_CAP / HOLD_DAYS = 20%`씩 배정하면
최악일이 -723,062원 → **-160,000원**(4.5배), 굶는 날이 8일 → **0일**이 된다.

### 채택값

```
BOOK_CAP = 1.00   # 동시 보유 총노출 (현금 계좌는 1.0을 넘을 수 없다)
NAME_CAP = 0.10   # 종목당 (켈리 자체 캡 0.25보다 낮다 — 근거는 §2 꼬리)
DAY_CAP  = 0.20   # BOOK_CAP / HOLD_DAYS
```

### 0주는 배분이 아니다 — 그리고 떨어진 몫을 남에게 얹지도 않는다

트랜치 20%(200만원)를 26종목에 뿌리면 1종목당 약 11.6만원이 된다.
2026-08-26 배치 실측: **사이징 26건 중 19건이 0주**였다
(예: 배분 115,999원 < 1주 1,058,000원). 화면에 0주만 뜨면 버그로 읽힌다.

그래서 1주도 못 사는 행을 **하나씩** 떨어뜨리고 남은 행에 재분배한다.
떨어뜨리는 순서는 비중이 가장 작은 쪽, 동률이면 비싼 쪽.

다만 재분배는 **원래 요청 분율을 넘지 않는다**(`alloc = min(비례배분, raw)`).
떨어진 행의 몫을 남은 행에 얹으면 그건 엔진이 요청한 것보다 크게 거는
**새 베팅**이고, 어느 종목에 얹을지는 순위 판단이다 — §4에서 그 순위에
정보가 없음을 보였다. 그래서 남는 예산은 **그냥 쓰지 않는다.**

결과 (직전 4개 배치):

| 배치 | 분율 합계 | 수량>0 | 0주 | 집행액 | 원래보다 커진 행 |
|---|---|---|---|---|---|
| 2026-08-21 | 92.8% → 19.97% | 7 | 0 | 1,665,050원 | 0 |
| 2026-08-24 | 169.0% → 19.97% | 6 | 0 | 1,874,870원 | 0 |
| 2026-08-25 | 117.2% → 19.97% | 13 | 0 | 1,652,235원 | 0 |
| 2026-08-26 | 97.0% → 19.96% | 7 | 0 | 1,729,960원 | 0 |

`PRODUCTION_BUY`·`TOP_PICK` 건수는 네 배치 모두 무변경.

### 무엇을 바꾸지 않는가

- 추천 목록·`PRODUCTION_BUY`·`TOP_PICK`·순위 **무변경**
- 분율을 **줄이기만** 한다. 어떤 행도 원래보다 커지지 않는다 (`scale ≤ 1`, 테스트로 고정)
- 원값은 `KELLY_FRACTION_RAW`·`켈리_금액_RAW(원)`에 보존

### 전환 처리

예산 도입 이전 배치는 집행 불가능한 분율(합계 최대 184%)을 그대로 적고 있다.
그걸 '보유 중'으로 세면 신규 배분이 영구히 0이 된다 — 실제로 보유한 적 없는 포지션이다.
그래서 `BUDGET_SCALE` 컬럼이 없는 과거 배치는 **그날 예산 레이어가 허용했을 만큼으로
되돌려** 센다(워밍업 두고 순차 재생). 도입 후 배치는 이미 예산이 반영돼 있으므로 그대로 쓴다.

## 2. "-8% 손절"은 시장이 지켜주는 약속이 아니다

패널에서 손절 발동 100,012건을 재현했다.

| | 값 |
|---|---|
| 다음 시가가 이미 손절가 아래(갭 관통) | **9,488건 (9.5%)** |
| 갭 관통 시 실제 체결 평균 | **-10.59%** |
| 중위 | -9.47% |
| -15% 이하 체결 | 628건 |
| -20% 이하 체결 | 223건 |
| 최악 | **-79.17%** |
| 손절 1건당 과소평가 | -0.25%p |
| 전체 평균수익 영향 | -0.088%p |

평균 영향은 작다. 문제는 **꼬리**다. 종목당 25%를 넣은 상태에서 -79% 체결이
한 번 나오면 계좌의 20%가 하루에 사라진다.
**종목당 상한을 25% → 10%로 낮춘 근거는 기대값이 아니라 이 꼬리다.**

발동일 분포: D+1 21% · D+2 28% · D+3 22% · D+4 16% · D+5 13%
(진입가능 279,488행 기준 발동률 35.8%)

## 3. 손절 발동 자체는 모델대로였다

`fwd5_del100` 268,016행 중 -8% 이하로 끝난 행은 111,130건(41.5%)이고,
그중 111,046건이 정확히 -8%~-8.5% 구간이다. -8.5%보다 나쁜 84건은 전부
상장폐지(-100%)다. 즉 **SSOT의 손절 체결 가정 자체에는 버그가 없다** —
가정이 낙관적일 뿐이고, 그 낙관의 크기가 §2다.

## 4. 켈리의 승률은 노이즈다 — 고치지 않았다

먼저 잘못 읽었던 것을 정정한다. 후보 전체(45,837행)로 보면 선언 승률은
**역전**돼 보인다 — 선언 46.6% 구간의 실현 승률이 18.7%로 가장 나쁘고,
선언 30% 구간이 48.4%로 가장 좋다. OOS에서도, 분기 3/4에서도 같은 방향이다.

**그러나 그 역전은 실제로 돈이 걸리지 않는 행이 만든다.**
사이징 대상(`켈리_수량>0`)은 45,837행 중 **1,664행(3.6%)** 뿐이고,
그 안에서 선언 p를 다시 보면:

| | 값 |
|---|---|
| 풀링 상위−하위 | +2.17%p (t=3.58, p=0.0004) |
| IS 상위−하위 | -0.16%p |
| OOS 상위−하위 | -0.26%p |
| **일별 계열 (날짜 통제)** | **-0.18%, HAC(5) p=0.7340, 양수일 33%** |

풀링 +2.17%p는 **날짜 구성 효과**다. 같은 날 안에서 비교하면 사라진다.
즉 사이징 대상 안에서 선언 p는 **역예측도, 예측도 아니다 — 정보가 없다.**

켈리 가중과 균등 가중의 차이도 없다: -0.15%p (HAC p=0.7123).

수준은 여전히 틀려 있다 — 사이징 대상 선언 53.3% vs 실현 28.3% (**+25.0%p**).
b=1.80에서 실현 승률로 켈리를 풀면 `f = 0.283 − 0.717/1.80 < 0`,
즉 **베팅하지 말라**가 나온다.

그래서 "선언 p를 실현 p로 교체"는 리스크 개선이 아니라 **전략 중단**이다.
그건 사이징 파라미터가 아니라 §5의 문제이고, 여기서 결정할 사안이 아니다.
v76은 수준 오차를 **노출 상한으로 흡수**한다 — 틀린 확률로 크게 걸지 못하게.

## 5. 예산 레이어가 고칠 수 없는 것

전략의 기대수익이 음수인 건 사이징 문제가 아니다.
원인은 편입 게이트의 역예측성이다 (`PREDICTIVE_POWER_20260827.md` §8:
편입일 -2.36% vs 제외일 -0.00%, OOS BH-FDR 4/4 통과).

예산 레이어가 하는 일은 **음수 기대값에 레버리지를 얹지 않는 것**뿐이다.
그것만으로 MDD가 -173% → -52.6%로 줄고 계좌가 살아남는다.
살아남는 것과 이기는 것은 다른 문제다.
