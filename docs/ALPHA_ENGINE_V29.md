# v29 — ALPHA_SCORE: 검증 통과가 조건인 예측 점수

> 2026-07-14 · "점수가 높으면 실제로 오를 확률이 높아야 한다"는 요구의 구현.
> v28이 진단(축 역주행 감시)이었다면 v29는 치료(예측되는 점수의 재건)다.

## 1. 무엇을 만들었나

`alpha_engine.py` — 과거 일별 추천 CSV + OHLCV 선행수익률로 학습하는 GBDT 랭킹 모델.

- **입력**: 운영 중 매일 생성된 recommend CSV의 수치 피처 ~94개 (가격 레벨·기존 합성점수 제외).
  CSV는 당일 장 마감 후 생성된 운영 산출물이므로 **구조적으로 lookahead 불가**.
  시장폭 등 시장 레벨 변수가 입력에 포함되어 **장세에 따라 판단이 바뀌는** 점수가 학습됨.
- **타깃**: t+1 시가 진입 → t+6 종가 청산 수익률의 당일 횡단면 백분위 (실거래 기준).
- **안전장치**: CARRY 행 제외, CSV 종가=실제 종가 1% 이내 행만 사용(stale 오염 차단),
  누출 검사(`ret_*` 컬럼이 과거 수익률임을 corr=1.000으로 확인).

## 2. 검증 (2026-07-14 최초)

월 단위 워크포워드 (해당 월 이전 데이터로만 학습 → 그 월 예측):

| 지표 | ALPHA | FINAL_SCORE | ELITE_SCORE |
|---|---|---|---|
| OOS 일평균 IC | **+0.15~0.20 (t=+7)** | -0.037 | -0.065 |
| OOS AUC (5일 승패) | **0.61** | 0.525 | 0.499 |
| Q5-Q1 스프레드 | **+5.1%/5일** | +0.4% | -0.9% |

**십분위 캘리브레이션 (승률 단조성 복원):**

| 알파 백분위 | 실측 승률 | 평균 수익률 |
|---|---|---|
| 상위 0~10% | **41%** | -1.25% |
| 상위 10~20% | 36% | -2.52% |
| … | 단조 감소 | … |
| 하위 0~10% | **24%** | -7.61% |

(OOS가 폭락 구간이라 절대 수익률은 음수지만, **순서**가 완벽 단조 — "고점수=고확률" 복원)

## 3. 정직성 계약 (v26 ML gate 철학 계승)

매일 밤 파이프라인이:
1. 전체 이력으로 패널 재구축 → 월 워크포워드 재검증
2. **OOS IC t≥2 AND AUC≥0.52 AND Q5-Q1>0** 전부 통과 → 모델 저장, 다음날 `ALPHA_VALIDATED=1`
3. 하나라도 실패 → 저장 안 함 → 다음날 자동 미사용 + 화면에 "AI 예측 미사용" 명시
4. 검증 수치는 `data/alpha_model_meta.json`에 그대로 공개

## 4. 사용처 (검증 통과 시에만)

| 사용처 | 규칙 | 실측 근거 |
|---|---|---|
| 순위표 정렬 | ALPHA_SCORE를 ELITE보다 우선 | 알파만 OOS 단조 |
| 픽 바닥 필터 | 당일 알파 하위 30% 후보 제외 | 픽 평균 +3.51%→**+4.20%**/건 |
| 근거 문장 | "AI 알파모델 예측 상위 X% — 이 구간 실측 승률 Y%" | 캘리브레이션 테이블 |

**의도적으로 하지 않은 것**: 픽 정렬을 알파로 교체 — 게이트 통과 후보군 내에서는
POC 근접 정렬(+3.51%)이 알파 정렬(+2.25%)보다 우월했다. 알파의 힘은 넓은 유니버스의
순서(IC)이지, 이미 걸러진 3~4개의 미세 순위가 아니다. 데이터가 시키는 대로 썼다.
