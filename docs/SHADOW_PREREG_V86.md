# 선별 그림자 선등록 판정 규칙 (v86)

> 등록 버전 `v86-20261109` · 코드 SSOT: `services/selection_shadow.py`
> (`PREREG_*`, `REGISTERED_FROM`, `THIN_POOL_MAX`, `prereg_verdict`).
> 이 문서와 코드의 숫자는 **결과를 보기 전에** 고정한다. 결과를 보고 규칙·풀·랭킹을
> 바꾸면 그 변형은 무효이며, 새 이름·새 등록일로 다시 시작한다.

## 1. 왜 다시 등록하는가

v86 점검(랭킹·손실 원인 연구, 독립 재현 완료)의 결론:

- 프로덕션 랭킹(알파×clip(RR,0,3)×1000 + 품질점수)과 알파/변동성/품질 게이트, risk_off
  문턱은 **그대로 둔다** — 더 나은 대안이 강건하게 입증되지 않았다.
- 기존 그림자 `lowvol`의 +4.2%p(18일, p=0.057)는 09-14 이후 하락장 한 에피소드에서 나왔다.
  65일로 넓히면 +0.20%p(p=0.90), 09-14 이전은 부호가 반대다. 18~20일로는 랭킹 규칙이
  갈리지 않는다(반기 부호가 뒤집힌다) → 기존 `TARGET_DAYS=20` 판정 문구를 폐기한다.
- 후보 가설은 그림자로만 남기고 **등록 이후 새 표본**으로만 판정한다.

## 2. 변형 (전부 관찰 전용 — PRODUCTION_BUY·켈리·목록 무변경)

| 변형 | 풀 | 1등 | 역할 |
|---|---|---|---|
| `live` | 현행 공식픽(PRODUCTION_BUY). 차단일엔 재구성 풀 | 현행 키 | 기준 |
| `legacy` | v83 이전(고변동 게이트 없음) | 알파×RR | 참고 — 상태 `탐색` 고정 |
| `lowvol` | 리스크가드·급등·v83 변동성·RR≥1.3·POC·활성 ROUTE | ATR% 최저 | 후보 |
| `ext_lowtv` | 캐시 ∪ 레인(≈1,200종목), 선등록 5특징(v1-20261006) | 분위 평균 최저 | 후보 |
| `comp_lowvol` | `lowvol`과 같은 풀 | pct(ALPHA_SCORE)+pct(-ATR%) (그날 풀 안 분위) | 후보 (신규) |
| `no_alpha` | 현행 풀에서 **알파≥문턱·저점추세만 제거**: 리스크가드·급등·v83 변동성·7월/회복 방어·BUY_NOW_PASS·공통 품질가드(매크로·이상이력·신선도·무결성·POC≤20·RR≥1.3)·사이징 가능 ROUTE | 현행 키 | 후보 (신규) — "알파 게이트 풀이 기반 풀보다 하루 -1.0~1.3%p 뒤진다"는 발견의 검정 |
| `thin_skip` | `live`와 같음 | `live`와 같음, 단 그날 TOP_PICK ≤ 5 이면 **현금(수익 0)** | 후보 (신규) |

- 현행 키 = `ALPHA_SCORE × clip(RR_NOW_TP1, 0, 3) × 1000 + QUALITY_GUARD_SCORE`
  (`recommendation_quality.apply_recommendation_quality_guard`와 동일).
- 재구성 현행 풀의 1등은 20260914~20261106 정상일 20일 전부에서 기록된 PRODUCTION_BUY와
  일치했다(픽이 없던 10/01 포함).

### risk_off 차단일

전 행이 `NEW_ENTRY_BLOCKED`인 날(시장 전체 차단)에도 모든 변형의 **반사실 픽**을
`blocked=1`로 기록한다: 차단을 무시하고 봉인 전 ROUTE(`ROUTE_PRE_BLOCK`)로 같은 규칙을
적용한다. 7월/회복 방어 같은 행 단위 차단은 유지한다. thin_skip의 TOP_PICK 수는 재구성
알파 게이트 통과 수로 센다. `ext_lowtv`는 원래 매일 기록했고 이제 같은 플래그를 단다.
요약은 **정상일/차단일을 따로** 내고, 페어드 통계는 **양쪽 변형이 모두 실현된 날만** 쓴다.

## 3. 판정 규칙 (후보 vs `live`)

1. **표본**: `REGISTERED_FROM = 20261109`(v86 머지 후 첫 배치) 이후 배치만. 그 전 기록은
   `segments.exploratory`로만 보고하고 판정에 넣지 않는다 — 기존 `lowvol`·`ext_lowtv`도 같다.
2. **날**: 정상일(비 risk_off) 중 후보·live 모두 실현수익이 있는 날. 날짜순 **처음 40일 고정창**
   (40일을 넘겨 계속 보다가 좋을 때 멈추는 선택적 중단을 막는다).
3. **승격 후보** — 넷 다 만족:
   - 페어드 차이(후보−live) 평균 > 0 이고 HAC(Newey-West, lag 5) 양측 p < 0.05
   - 앞 20일·뒤 20일 반기 평균 차이의 부호가 전체와 같음
   - 후보의 40일 평균 수익에서 매매일마다 왕복 비용 0.25%를 뺀 값 > 0 (thin_skip 현금일은 비용 0)
4. 하나라도 못 넘으면 **기각**. 40일 전에는 **측정 중 n/40**.
5. `legacy`는 후보가 아니라 상태 **탐색**.
6. 승격 후보여도 코드는 아무것도 바꾸지 않는다 — 사용자가 판정하고 별도 버전으로 반영한다.

실현수익 SSOT: `services.pick_history._realized` (t+1 시가 진입 · -8% 장중 손절 · t+5 종가).

## 4. 출력

`data/selection_shadow_latest.json` (NaN → null, `allow_nan=False`):

- `statuses`: 변형별 `탐색` / `측정 중 n/40` / `승격 후보` / `기각`
- `verdicts`: 후보별 n, 창, 차이, HAC t/p, 반기 평균, 비용 차감 평균, 개별 조건 통과 여부
- `variants[v].segments.{exploratory,registered}.{normal,blocked}`: 일수·평균·승률·손절률·HAC
- `paired["후보-live"].segments.{exploratory,registered}_{normal,blocked}`

화면(결정 센터 '검증 중' 🪞 줄)은 상태를 묶어 한 줄로 보이고, 승격 후보가 생기면 따로 알린다.
