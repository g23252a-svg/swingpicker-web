# 추천 데이터 신뢰성 패치

## 해결한 문제

- 로컬 CSV가 있으면 새로고침 버튼도 원격 최신 데이터를 확인하지 않았습니다.
- 실제 `기준일`을 읽지 못하고 시스템의 오늘 날짜를 표시했습니다.
- 다운로드한 내용을 검증 전에 캐시에 덮어써 잘못된 응답이 정상 파일을 대체할 수 있었습니다.
- 동시 새로고침이 겹치거나 더 오래된 원격 파일을 받았을 때 상태를 보호하지 못했습니다.
- 양의 무한대 손익비와 잘못된 가격 관계가 추천 후보 판정에 들어갈 수 있었습니다.
- OHLCV 파일명만 과거 시점으로 제한했고, 파일 내부의 미래 거래일은 제한하지 않았습니다.

## 변경 내용

### 새로고침과 복구

`DataStore.refresh(force_remote=True)`는 로컬 파일 존재 여부와 관계없이 원격 데이터를 확인합니다. 메인 화면 새로고침 버튼에 연결했습니다. 기본 `refresh()`는 기존의 로컬 우선 초기 로딩을 유지합니다.

로컬·원격·메모리 후보 중 검증 가능한 가장 최근 기준일을 선택합니다. 같은 날짜라면 원격 수정본을 우선합니다. 원격 조회 실패 시 정상 로컬/메모리 자료를 유지하고 화면에 실패를 알립니다. 데이터가 전혀 없으면 성공 알림을 내지 않습니다.

캐시는 검증된 원본 데이터만 임시 파일에 기록하고 `os.replace`로 교체합니다. 저장 실패 시 기존 캐시는 유지합니다. 새로고침은 직렬화하고 데이터·기준일·상태를 함께 게시합니다. `scored` 읽기와 쓰기는 복사본을 사용합니다.

### 입력 검증

필수 컬럼, 빈 응답, 잘못된 종목코드, 중복 코드, 섞인 기준일, 기준일 컬럼 간 불일치를 검증합니다. 숫자 종목코드의 앞자리 0과 `0126Z0` 같은 영문 포함 6자리 코드를 지원합니다. 날짜 컬럼이 없는 과거 파일은 읽되 기준일을 `확인 불가`로 표시합니다.

추천 품질 가드에는 `INPUT_INTEGRITY_OK`를 추가했습니다. 존재하는 가격·손익비 컬럼의 결측/무한대/0 이하 값, 손절가 < 진입가 < 1차 목표가 관계 위반, 활성 알파 점수의 비정상 값을 공식 매수에서 제외합니다. 해당 컬럼이 없는 레거시 데이터는 기존 호환성을 유지합니다. 오류 사유는 `가격·손익비 입력 오류 — 수집 데이터 확인 필요`로 명시합니다.

정책 식별자는 `alpha_gate_v62_input_integrity_v1`입니다. 알파 임계값, 시장별 진입 전략, 하루 1종목 제한은 변경하지 않았습니다. 다음 배치 전 구 정책 CSV에 대한 브리핑의 정책 일치 검사는 기존 설계대로 SKIP될 수 있으며, 화면 로딩 시 현재 품질 가드를 다시 적용합니다.

### 화면과 시점 검증

오늘의 결정 화면에서 추천 기준일과 실제 가격 기준일을 따로 표시합니다. 가격이 배치보다 이전이면 이전 거래일 가격 안내를 보여주고, 날짜가 없으면 확인 필요로 표시합니다. 휴장일 표시만으로 매수 정책을 새로 바꾸지는 않습니다.

OHLCV 캐시 안의 거래일도 배치 기준일 이하로 제한합니다. ISO 날짜와 YYYYMMDD를 정규화하고, 행 번호 인덱스를 1970년 가격일로 잘못 읽지 않습니다. 중복 거래일은 한 번만 파싱합니다.

## 검증

- 신규 회귀 테스트 32개: 정상/비정상 원격 응답, 역행 방지, 같은 날짜 수정본, 원격 장애, 캐시 저장 실패, 동시 갱신, 복사 격리, 입력 오류, 미래 캐시 행, 날짜 표시.
- 확대 회귀 테스트: 358 passed, 1 skipped (180.31초). 이후 추가된 3개 사례를 포함한 신규 회귀 파일 32개도 모두 통과했습니다.
- 순환 참조/레이어 검사, silent-exception 검사, Contract Gate 13단계 모두 통과.
- 실제 추천 데이터로 NiceGUI 결정 화면 156개 요소 생성 및 두 기준일 라벨 확인.
- 저장소 `recommend_latest.csv` 358행을 이전/새 품질 가드에 각각 입력: 공식 매수 1개 → 1개, 공식 매수 판정 변경 0행. 실제 기준일은 20260903.

이 검증은 데이터 처리와 추천 계약의 정확성을 확인합니다. 미래 수익률 상승을 입증하는 백테스트 또는 실거래 검증은 아닙니다. 실제 외부 시세 수집·인증·결제·운영 배포는 이 패치의 검증 범위에 포함하지 않았습니다.
